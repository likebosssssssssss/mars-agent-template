# server-ops.md — работа с сервером Агента по SSH/git

> Читать когда: правите что-то в `~/workspace/` через SSH, или решаете, что можно
> закоммитить в git на сервере.

## workspace/ — не только DNA-файлы

Бот сохраняет всё, что ему присылают в Telegram (фото, документы, видео), в
`~/workspace/.media/`. Иногда там же в корне `workspace/` со временем накапливаются
и другие рабочие файлы — конвертированные документы, транскрибации, черновики,
которые бот создал по ходу работы. Среди них может быть личная, финансовая или
конфиденциальная информация владельца агента.

Это не часть архитектуры Агента — просто побочный эффект того, что бот пишет
результаты своей работы в ту же папку, где лежат DNA-файлы.

## Область git-трекинга — только DNA-файлы + knowledge/

`setup-server.sh` уже создаёт `~/workspace/.gitignore`, который разрешает
коммитить только:
```
CLAUDE.md SOUL.md MEMORY.md GOALS.md LEARNED.md
USER.md MISSION.md PROJECTS.md PREFERENCES.md
knowledge/
```
Всё остальное игнорируется по умолчанию (`*` + explicit `!` на разрешённые пути).

**Жёсткое правило при любой ручной работе на сервере:** никогда не `git add .`
или `git add -A` без проверки `git status` перед коммитом — если видите
незнакомый файл в staged, остановитесь и разберитесь, что это, прежде чем
коммитить. `.gitignore` защищает от случайного включения, но не от явного
`git add путь/к/файлу`, если кто-то укажет путь внутри `.media/` вручную.

## Многошаговые флоу по SSH (OAuth, интерактивный логин)

Если задача требует, чтобы состояние (открытый URL, ожидание кода) пережило
переход к следующему сообщению пользователя — используйте `tmux`/`screen` с
первого шага, а не одиночные SSH-команды по очереди. Одиночная команда каждый
раз запускает новый процесс с нуля и рвёт состояние предыдущего шага —
например, свежий `claude /login` инвалидирует URL и код от предыдущего запуска.
